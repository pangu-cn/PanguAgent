## 2b. 内置浏览器（F9，CDP 原生）

浏览器自动化原先只能通过外部 MCP 服务接入。那能用，但把浏览器放到了本项目所有保证
之外：会话是第三方进程，它的请求 Pangu 无法归属、无法闸门、无法计量。

现在直接讲 CDP 协议本身：`pangu-boundary::browser` 自己实现握手、帧编解码与
JSON-RPC，启动无头 Chromium 并驱动它。浏览器动作因此进入与其它工具**完全相同**的
L1–L4 链。

| 工具 | 风险 | 效果 | 为什么 |
|------|------|------|--------|
| `browser_open` | `NeedsHuman` | `ExternalRead` | 会访问**主机**，与 `http_fetch` 同类，必须声明 host |
| `browser_read` | `ReadOnly` | `NoEffect` | 读取当前页面，不改变任何东西 |
| `browser_screenshot` | `Reversible` | `Workspace` / `Reversible` | 页面本身不变，但 PNG 会写入运行产物目录；`NoEffect` 不能诚实声明这次写入 |
| `browser_click` | `NeedsHuman` | `ExternalMutation` / `Irreversible` | 点下去会发生什么**由页面决定**，且本程序无法撤销 —— 状态改动落在它不控制的服务器上 |
| `browser_type` | `NeedsHuman` | `ExternalMutation` / `Irreversible` | 输入可能触发会行动的处理器，同样无法撤销 |

**最关键的一条：点击不是只读。** 把它当成观察，会让一个改变状态的动作绕过人工闸门 ——
和"信任对方声明的 `readOnlyHint`"是同一类错误。

### 几个刻意的选择

- **默认关闭**：不配置时浏览器工具**根本不出现在工具表里**。模型无法调用一个操作者
  没有开启的能力。已验证：无视开关无条件广告会让"未配置时不广告"的测试失败。
- **点击走真实鼠标事件**，不是 `element.click()`。合成 DOM 点击不经过命中测试，会在
  一个被浮层遮住或滚出视口的元素上触发，而调用方会以为发生了真实的用户操作。
- **打字是逐字符按键**，不是一次 `Input.insertText`：后者不触发大多数框架监听的按键
  事件，表单看起来被填好了，但它的处理器从未运行。
- **截图写进 run 自己的产物目录**，与其它产物受同一套规则约束。
- **会话在 drop 时结束**：泄漏的无头浏览器会占住 profile 目录和端口，让下一次运行
  因为与自己无关的原因失败。

### 实测（本机真实 Chrome 154）

9 个端到端测试驱动真实浏览器，全部通过，且断言的是**页面自己的效果**：

- CDP 应答：`Chrome/154.0.8037.98`
- 导航后标题与正文文本正确
- 截图 4148 字节，PNG 签名校验通过
- **点击**：页面自己的 `onclick` 把标题改成 `clicked` —— 证明点击真的送达了元素
- 打字后输入框的 `value` 为 `hi`
- 选择器无匹配：拒绝并点名该选择器，不是静默无操作
- 未知方法：真实 CDP 错误 `code -32601`
- drop 后 profile 目录被释放（进程已回收）

真实浏览器测试默认 `#[ignore]`，需显式运行：

```text
cargo test -p pangu-boundary --test browser_cdp -- --ignored
```

标 `#[ignore]` 而不是静默跳过，原因与容器测试相同：悄悄什么都不做的测试报告的是它
没有挣到的成功。

### 诚实的限制

- **浏览器不在沙箱里，除非操作者声明了 runtime**。`[browser] network` 限制页面能做
  什么，**不是**沙箱。真隔离是 `[execution] runtime` 的职责；两者都配置时，浏览器
  进程会通过该 runtime 的启动器拉起。
- 只支持 `http`/`https`；`file:` 会被拒绝（否则浏览器会去读宿主机文件系统）。

## 1. 安全沙盒：真运行时适配器

`[execution] runtime` 是一个**强制**字段，不是审计声明。它与 `profile` 分开，
因为两者承诺不同：

| 字段 | 含义 | 是否强制 |
|------|------|----------|
| `profile` | 操作者声明进程在哪里运行 | 否——仅审计 |
| `runtime` | 命令真正在哪个 OS 级沙箱里执行 | **是** |

支持四种取值：

- `local`（默认）：在宿主机直接执行，行为与以前一致。
- `auto`：按**内核边界强度**择优——`firecracker` > `gvisor` > `oci`。
- `firecracker`：微 VM，独立内核（最强边界）。
- `gvisor`：`runsc` 用户态内核。
- `oci`：Docker/Podman 容器（namespace + cgroup）。

### 探测：声明不等于可用

声明非 `local` 后，Pangu 会**真正在里面跑一条命令**来探测。只看二进制是否存在
是不够的——那样会把"守护进程没起来""镜像没拉""内核模块没加载"都报成可用。
探测报告的是**观察到的行为**（跑通了什么），不是无法支撑的安全断言。

### fail-closed：为什么没有退回宿主机

探测失败时命令**被拒绝**，不退回宿主机。理由是审计诚实：运行记录里写着操作者
声明的运行时，实际却在宿主机上跑，会让这条记录变成假的——操作者会以为自己拥有
并不存在的隔离。`local` 仍然可用且诚实，但必须是**主动选择**的，不能是失败后的
兜底。

拒绝信息会说明：哪个运行时不可用、为什么、审计为何不容许退回、以及怎么修。

### 诚实的限制

- **Firecracker 尚不能真正驱动到完成**：把命令送进去、把输出取出来需要 vsock 或
  串口通道，尚未实现。它会被**识别**并在 `auto` 里优先，但当前始终报告不可用。
  这是刻意的：声称一个从不启动的微 VM，正是本特性要消除的那类失败。
- **`profile` 单独使用时仍然是声明**：只写 `profile = "container"` 而不写
  `runtime`，审计里会记录该声明，但命令仍在宿主机上跑。要真隔离就必须写
  `runtime`。
- 探测**不验证隔离是否无法逃逸**：那是运行时自身的属性，启动器无法证明。

### 修复的两个真实缺陷

第二个是在写 `runtime_dispatch.rs` 的收尾测试时暴露的，它让"声明即强制"在**真实启动
路径**上根本不成立——探测通过之后命令仍然发不出去：

1. **子进程工作目录用了容器内路径。** `docker` 进程本身是在宿主机上被拉起的，而
   `current_dir` 被设成了 `/workspace`——那是命令在**沙箱内**看到的路径，在 Windows
   上不存在。结果是每条沙箱命令都以 `os error 267（目录名称无效）` 失败，运行时从未
   启动。现在区分两者：启动器进程用宿主机工作区，传给命令的 cwd 才是挂载点。

2. **探测用的 `PATH` 和执行用的 `PATH` 不是同一个。** 探测继承父进程环境，真实执行
   用的是操作者 allow-list 清洗后的环境。因此一个"探测通过"的运行时可能**根本无法
   启动**：探测因为父进程 `PATH` 里有 `docker` 而成功，子进程的 `PATH` 里没有。现在
   在探测时就把启动器解析成**绝对路径**并固定下来，使"通过探测的运行时"和"执行命令
   的运行时"按构造是同一个文件，而不是碰巧相同。

另外修掉了 `[boundary.env] allow` 的大小写问题：配置同时列出了 `PATH`/`SYSTEMROOT`，
而 Windows 实际报告 `Path`/`SystemRoot`。原先的精确大小写查找**静默丢掉这两个变量**，
导致每个沙箱子进程都没有 `PATH` 和 `SystemRoot`——Windows 加载器需要 `SystemRoot` 才能
找到系统 DLL，所以命令以 `os error 2` 失败而不是运行。现在按大小写不敏感匹配。

### 验证方式：真把命令塞进去，而不是等 Docker

"真拉起执行"这句话在**没有可用容器运行时的机器上**同样必须能被验证。容器运行时二进制
被一个**记录 argv 的桩**替换（放在 `PATH` 上，走真实的 `find_program` 查找），于是生产
代码路径一字未改，而以下事实可以逐条断言：探测找到了程序、构造了带隔离标志的 argv、
执行了它、读回 stdout 并匹配到 token、随后一次**真实工具调用**走了同一套 argv。

实测记录（Windows 10.0.19045，本机 Docker Desktop 的 Linux 引擎不可用）：

```
RAN docker run --rm -i "--volume=<ws>:/workspace" "--workdir=/workspace" \
  "--cap-drop=ALL" "--security-opt=no-new-privileges" alpine:3.20 pwd
```

不声明运行时则记录为 `RAN pangu-local-wrapper`——**没有任何容器包装**，这条反向用例
防止"把每条命令都塞进运行时"这种改法悄悄通过。

桩**不能**证明、本文档也不声称：Docker 对这些标志的实现真的隔离了什么。那是运行时
自身的属性，与 `runtime.rs` 里写明的限制是同一条。

## 2. 持久化执行环境：为什么仍是"声明层"

"持久化执行环境"没有实现：每次工具调用是一个独立进程，不保留 shell 状态、
环境变量或工作目录变更。沙盒解决的是**隔离**，不是**持久性**——两者是不同的问题，
后者需要一次明确的设计（生命周期、状态存放位置、崩溃后的处理），不是给现有结构
加一个字段。

## 4. MCP 协议支持

分两部分实现：

**协议核心**（`pangu-core::mcp`）：JSON-RPC 2.0 编解码、请求 id 分配、响应
与通知的区分、工具列表与调用结果的解析。协议版本 `2025-06-18`。`initialize`
**只声明 `tools`**，从不声明 `sampling` 或 `roots`——声明一个我们不打算实现
的能力，等于邀请对方向我们要它。

**适配层**（`pangu-toolkit::mcp_stdio` + `mcp_executor` + `pangu-boundary::mcp`）：

- 传输用 stdio，`env_clear()` 后只传显式声明的环境；`kill_on_drop(true)`；
  stderr 有界并发排空；逐次读取有截止时间；帧上限 8 MiB。
- **配置即授权**：只有 `boundary.toml` 里声明的外部工具才会被广告出来。未声
  明的工具不会被广告，且会被报告。
- **`readOnlyHint` 是受约束方自己的声明，永不参与风险判定**。有测试把
  `readOnlyHint: true` 映射为 destructive，断言 `assess()` 返回
  `Risk::Destructive`——因为风险由**我们的映射**决定，不由对方的注解决定。
- `isError` 响应转成 `Err`，使一次被拒绝的操作不可能变成证据。
- 非文本内容块**被命名而非内联**。
- 外部工具的**描述文本被加前缀标注**为服务器提供的数据、不是指令。

**如实记录的限制**：`assess()` 无法知道一个外部工具到底会碰到什么。映射只
约束了 **Policy 能看到什么**，不约束那个进程实际做了什么。这个限制写在模块
文档里，不藏在注释里。

## 5 与 6. 分层记忆与项目隔离

三层，按"这个事实在哪里成立"划分——这也决定它可以在哪里写入：

| 作用域 | 存放位置 | 对谁成立 |
|--------|----------|----------|
| `Global` | `~/.pangu/memory/` | 此用户的所有项目 |
| `Project` | `<workspace>/.pangu/memory/` | 此仓库 |
| `Session` | 仅在内存 | 仅本次运行 |

**Global 层对运行只读，且这是构造上的**：项目目录是用户从陌生人那里 clone
来的。若运行能写 Global，打开一个不可信仓库就会让它的 agent 植入对所有其它
项目生效的记忆——这是跨项目的权限提升。因此
`MemoryScope::Global::is_writable_by_run()` 恒为 `false`，**没有任何配置组合
能打开它**。全局记忆只能由操作者 CLI 写入（`contribute_globally`）。

**跨项目记忆带键而非合并**：`ProjectKey` 由工作区**路径的规范化摘要**导出，
不是项目自称的名字——否则一个仓库可以冒充另一个项目，让自己的记忆被归到那
边。注入文本会说明某条全局记忆**是哪个项目贡献的**，这正是"事情本来就这样"
与"另一个项目当初这么做"的区别。

注入顺序 Session → Project → Global，让更具体的事实优先被读到；每行都带作用
域与来源标注，块首明确声明这些是**数据不是指令、不携带任何授权**。

Session 记忆永不落盘：被取消的运行留不下状态。

**记忆不改变授权模型**：分层只改变文本存在哪里、注入到哪里。全局层来的记忆
与项目层来的记忆携带完全相同的（零）权限。

## 7. 可视化 Trace

时间线是 Journal 的**投影**，带 `derived: true` / `authoritative: false`。
删掉它不丢任何东西，随时可从 Journal 重建。

- 行序按 **seq（封存序）**，不是 `at` 时间戳：时钟会走偏或说谎。
- 严重度由**事件类型**推导，**绝不由消息文本推导**：模型能写消息，让文本驱
  动展示等于让运行自己粉饰自己的审计记录。
- 成对事件配成 span；有 `call_id` 时用它作键，否则用 turn + 工具名（否则同
  一 turn 的并发调用会被并成一个）。
- **未闭合的起始事件报成 open，不是零长度 span**：运行在工具执行中被杀，不
  能看起来像一个很快的工具。只有结束、没有起始的事件不会被编造成 span。
- 时长优先用事件自带的 `duration_ms`，而不是两个时间戳相减；没有记录就如实
  说"没有记录的时长"。

输出：终端文本、SVG（自包含、无脚本、无外链）、Markdown。

## 8. 审计日志

**导出**而非第二套权威：单个自描述文件，可交给没有工作区的人。

**"tamper-evident" 的诚实含义**：导出携带事件数组的 SHA-256，并重新推导
Journal 的哈希链。它能检出导出内被编辑/重排/插入/删除的事件，以及声明的链
与自己内容不符。它**不能**检出把整份导出一致重写的攻击者——链没有锚定到任
何外部权威（无签名、无外部时间戳）。**这条限制写在每个导出文件内部**
（`INTEGRITY_STATEMENT`），让只拿到文件、没有源码的收件人也不会误以为这是它
不具备的密码学保证。

验证结果分两个结论，因为它们回答不同问题：

- `ok` —— 导出自身完整（摘要一致、顺序递增、无链断裂）。
- `chain_verified` —— 每条链接都带链且都对上。

无法做链校验的链接（v1 遗留记录）进 `notes` 并清掉 `chain_verified`。把"我
没法检查 X"报成"X 是坏的"，与把被跳过的 CI job 当成失败是同一个错误。

只导出事件（Journal 里已脱敏的形态）+ 计数 + 链头，**不**顺手带上工具输出与
模型原文：审计导出该包含"决定了什么"，不是"说了什么"。运行关于自身的说法
（模型、相位）记为 `Claim { is_claim: true }`。

## 9. Web UI 画布

`pangu canvas` 在 `127.0.0.1` 上提供 trace 与审计导出的可视化。

**构造上只读**：画布只提供记录的视图，**不存在任何能启动运行、批准任何东
西、写文件或改变状态的代码路径**——不是配置项，是这样写的代码里根本没有。
理由是浏览器页面是系统里最不可信的组件：它渲染模型产出的文本，也是敌意字符
串唯一可能变成动作的地方。如果画布能批准动作，那么页面上一条模型写就的消息
就会挨着一个授权它的按钮。保持只读意味着页面最坏只能误导人——那是复核问题，
不是权限提升。

路由只有四个：`/`、`/api/trace`、`/api/audit`、`/trace.svg`；其它一律 404，
非 GET 一律 405。

**只绑定回环 + 默认要 token**（16 字节 OS 随机数，常数时间比较）：审计视图
可能包含私有仓库的路径与消息。实测**每一条路由（包括 404 的）在无有效 token
时都返回 401**——未认证方连探测存在哪些路由都做不到。

所有插值走同一个转义函数；响应带 `nosniff`、`no-store` 与
`default-src 'none'` 的 CSP，因此即使转义出 bug 让标记漏进来，注入的脚本也不
会执行。

## 10. Skill 生态

六个包在 `skills/`，均为 `SKILL.toml` + `SKILL.md`、**不声明脚本**（B2 没有
执行它们的原语，声明等于宣传不存在的能力）。

自有风格的三条规则：

1. **每条结论都要能被别人重新推导**；
2. **区分"已验证"与"未验证"**，未跑的命令一律写 `not run`，绝不报告没有观
   察到的命令输出；
3. **写明本 skill 不做什么、不保证什么**。

`boundary-check` 是唯一涉及授权的 skill，因此文档开头即声明
**advisory、authorizes nothing**：真实运行的 L1–L4 求值才是唯一授权，"预测会
通过"不等于"被批准"。

安装与完整性：`pangu skills install <dir>`（仅操作者，运行没有安装或修改路
径）。每个文件进 `skill.lock` 的 SHA-256，可选 ed25519 签名。实测：篡改已安
装的 `SKILL.md` 后，`skills verify` 报 hash mismatch，且注册表把它标为
`REJECTED` 而不再广告——有声拒绝，不是静默跳过。

## 共同性质

下列性质贯穿以上各项，它们是这套实现的设计约束而非事后补充：

- **派生视图标注来源**：trace、审计导出、画布一律带 `derived: true` /
  `authoritative: false`，并在文本中指向 Journal。
- **未知输入 fail-closed**：未知的审计 schema 被拒绝解析，不是抱着希望去读。
- **边界由构造或配置固定，不靠约定**：Global 记忆的只读、画布的只读路由集、
  未声明的外部工具不被广告，都是代码里没有那条路径，而不是"请不要这样做"。
- **限制写在产物内部**：审计的完整性边界写进每个导出文件，画布页面写有
  "Journal is the authority"，外部工具的风险限制写在模块文档。收件人不需要
  读源码就能知道边界在哪。
