# ADR-0012：可执行 AI 客户端的界面方案

- 状态：Proposed（2026-10-08）。本文描述执行客户端，不新增权限。
- 关联：G5、E3、L1–L4。

## 1. 客户端做什么

Windows 与 macOS 是桌面执行端，Linux 是浏览器执行端。三端都做同一件事：操作者输入一条指令，客户端创建一次 `GoalContract`，然后显示模型、工具和审批的实时过程。

客户端不是只读看板。主按钮是“执行”。工具调用仍由服务端走 Policy、Sandbox、Approval 和 VerifiedAction；界面不能直接执行命令。

## 2. 方案 A：对话执行

```text
┌────────────────────────────────────────────────┐
│ Pangu 执行端          预算 12/40     运行中     │
├────────────────────────────────────────────────┤
│ 你：修复登录失败并给出验证结果                  │
│                                                │
│ Agent：先读错误日志                            │
│ 工具 read_file  logs/auth.log      已完成      │
│ Agent：失败来自过期 token                      │
│ 运行已暂停                                      │
├────────────────────────────────────────────────┤
│ 输入下一条指令…                         [执行] │
└────────────────────────────────────────────────┘

        ┌──────────── 风险确认 ────────────┐
        │ write_file src/auth.ts           │
        │ 风险 workspace-write             │
        │                                  │
        │ [拒绝]              [允许一次]   │
        └──────────────────────────────────┘
```

适合普通任务。指令在底部，执行过程按时间往上长。被 L4 拦住时，桌面端和 Linux Web 都弹出同一模态窗口，时间线本身不放确认按钮。

## 3. 方案 B：任务加工作区

```text
┌──────────────────────┬─────────────────────────┐
│ 指令与执行            │ 当前工作区               │
│ > 为导出接口补测试    │ src/export.ts           │
│ 1 搜索调用点  完成    │ + 新增断言              │
│ 2 读取实现    完成    │                         │
│ 3 写入测试    已暂停  │ diff 只读预览           │
├──────────────────────┴─────────────────────────┤
│ 继续这个任务，并运行 verify              [执行] │
└────────────────────────────────────────────────┘

              ┌──────── 风险确认 ────────┐
              │ 写入 tests/export.rs     │
              │ [拒绝]      [允许一次]   │
              └──────────────────────────┘
```

适合改代码。左侧是执行步骤，右侧只显示文件和 diff。风险确认使用与方案 A、Linux Web 相同的弹窗，不放在 diff 内。

## 4. 方案 C：运行控制台

```text
┌────────────┬───────────────────────────────────┐
│ 指令        │ 修复构建                           │
│ 状态        │ 第 3 步 / 最多 12 步              │
│ 当前工具    │ cargo test                        │
│ 已用预算    │ 0.04 / 1.00 USD                   │
├────────────┴───────────────────────────────────┤
│ [读取错误] 完成                                   │
│ [运行测试] 执行中················                 │
│ [修改代码] 已暂停，等待弹窗确认                   │
├────────────────────────────────────────────────┤
│ 新指令或补充约束                           [执行] │
└────────────────────────────────────────────────┘

                 ┌─────── 风险确认 ───────┐
                 │ cargo test             │
                 │ [拒绝]    [允许一次]   │
                 └────────────────────────┘
```

适合长时间任务。重点是当前步骤、预算和能否继续，而不是聊天文本。补充指令会开启新的约束，不会改写已经执行的步骤。

## 5. 共同行为

- “执行”创建一次新 run。空指令不能执行。
- 读操作在边界允许时直接出现进度；写入、命令和外部动作需要确认时暂停在该步骤。
- 不提供“全部允许”。可以提供“停止当前 run”。
- 停止只取消尚未开始的动作，不回滚已经成功的写入。
- Linux 浏览器端连接本机 `127.0.0.1` 服务。桌面端使用同一服务，避免两套执行逻辑。

## 5c. 风险确认弹窗

Windows、macOS 和 Linux Web 使用同一种模态确认。需要人工确认时，时间线只显示“已暂停”，确认内容出现在居中的弹窗中，背景不可操作。弹窗只提供“拒绝”和“允许一次”，没有“全部允许”。Linux Web 使用 `<dialog showModal>`；关闭弹窗而未选择视为拒绝。

## 5b. 命令输出

每次工具成功都把脱敏后的完整输出写入 `ToolFinished.payload.output`。事件同时带 `output_sha256`、`output_complete=true` 和 `collapsed=true`。界面默认显示最多 240 字节预览；展开后显示同一条完整记录，不另取一份可能不同的输出。

## 6. 建议

默认采用方案 A。它最直接表达“输入指令并执行”。方案 B 是代码任务视图，方案 C 是长任务视图，两者共用方案 A 的执行服务。
