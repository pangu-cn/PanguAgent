# ADR-0013：混合客户端外壳

- 状态：Accepted（2026-10-09）。外壳已实现；实时事件和完整 diff 仍待实现。
- 关联：ADR-0012、E3、L1–L4。

## 1. 借鉴范围

Pangu 客户端吸收五类界面习惯：

- DeepSeek Harness：左侧会话树、本地事件时间线和可折叠工具输出。
- Codex：底部指令栏、当前任务状态、逐步执行过程。
- Claude：长对话阅读、清晰的用户与 Agent 分段、风险确认独立于正文。
- WorkBuddy：产物优先，把报告、补丁和验证结果放在固定区域。
- GitHub Desktop：仓库变更列表、diff 预览、分支与提交入口。

这些只影响排布。模型输出、diff 和产物视图都是派生产物，不能成为授权。

## 2. 主界面

```text
┌────────────┬────────────────────────────┬──────────────┐
│ 沙箱        │ 当前对话                    │ 变更         │
│ ./.pangu   │ 你：修复登录失败            │ 3 个文件     │
│ 对话        │ Agent：读取日志            │ +12  -4      │
│ 归档        │ 工具输出 [展开]            │ diff 只读    │
│            │                            │              │
│ 设置        │ 运行已暂停                  │ 产物         │
├────────────┴────────────────────────────┤ report.md    │
│ 输入指令…                    预算  [执行] │ [提交…]      │
└─────────────────────────────────────────┴──────────────┘

                 ┌───────── 风险确认 ─────────┐
                 │ write_file src/auth.ts     │
                 │ [拒绝]        [允许一次]   │
                 └────────────────────────────┘
```

左侧保留现有沙箱、对话、归档和设置。中间是执行过程。右侧是 GitHub Desktop 式的变更与产物栏。

## 3. 四个界面区域

### 3.1 会话

会话按沙箱分组。普通对话和归档分列。选择一个对话后，中间区域只显示该会话 UUID 的记录。新建对话生成新的 UUID，不复用旧记录。

### 3.2 执行

底部指令栏只有一个“执行”按钮。一次点击创建一次 run，使用当前配置、当前沙箱和当前对话。运行中显示回合、当前工具、预算和“停止”。停止只取消尚未开始的动作。

### 3.3 变更

右侧显示工作区变更摘要和只读 diff。它提供“查看变更”和“准备提交”两个动作。准备提交只生成摘要，不执行 `git commit`。真正提交必须另经 L4，且不能附带 `--no-verify`。

### 3.4 产物

产物区只列出本次 run 已登记的交付物。没有验收证据时不显示“完成”。报告、补丁和测试结果都保留来源与 digest。

## 4. 明确不借鉴

- 不提供自动批准、`--yolo` 或全部允许。
- 不把客户端插件当作权限扩展。
- 不自动提交、自动推送或跳过 Git hooks。
- 不把模型总结、测试分数或界面状态当成验收。
- 不在界面保存长期 API key。默认成立：配置与 CLI 只记录密钥所在的环境变量名。**例外（2026-10-10，ADR-0015，操作者明确选择）**：桌面端自定义 Provider 的 profile 可明文存储 key（界面明示，key 不进事件/日志/上下文/workspace，环境变量模式保留）。

## 5. 当前实现差距

已实现的是沙箱、会话、归档、设置、配置选择，以及一次真实 run 的启动接线。**2026-10-11 更新**：第 1–5 步已全部落地——run 在后台线程执行并经 `RunSink` 流式送事件（`poll_run` 每帧抽干、`redact_event` 后渲染，行可展开看完整脱敏记录）；工具输出可折叠；右栏有只读 `git diff` 预览；产物栏直接读 `DeliverableStore::records()`（`complete` 与 `accepted` 可区分）；「准备提交」经风险确认 modal（L4）后才记录摘要，commit 本身仍是操作者手动执行。同期补充：`Agent::with_cancel` 协作式停止（turn/tool-call 边界检查，run 以 `aborted` 收尾）、工作区会话只读投影（自研最小 markdown 渲染器，不引第三方依赖）、「继续」恢复入口（resume_from 最近快照）、设置窗的 `doctor/explain` 与技能只读列表。

尚未实现：事件流内助手原文的富文本细节（当前投影自会话存储，需 `conversation.enabled`）、checkpoint/rollback 的 GUI 入口、canvas/trace 入口、web 端与桌面端的对齐。
